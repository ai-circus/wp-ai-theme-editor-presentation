Architecture, workflow, and security model for the Claude MCP bridge

Overview

What is this?

A bridge that lets Claude — via its Model Context Protocol (MCP) — read and edit the contextflow WordPress site directly: theme files, pages, posts, and custom post types.

Without this

  • Copy-paste content between Claude and WP admin
  • Manually upload template files via FTP
  • No brand context — Claude doesn't know the design

With this

  • Claude reads existing pages & templates directly
  • Creates and edits files in the active theme
  • Auto-loads design guide before any build task

Use cases

  • Build new landing page templates
  • Update content on product pages
  • Edit custom post type entries (e.g. customer-segments)

Authentication flow

How a session starts

Claude.ai (web UI) — OAuth 2.0 + PKCE

  • User adds MCP URL to Claude.ai as a remote connector
  • Claude.ai discovers OAuth endpoints via /.well-known/
  • User is redirected to the MCP server's login page
  • User enters their personal API key
  • Server issues an authorisation code → exchanges for access token
  • Claude.ai uses the token for all subsequent requests

Claude Desktop — Bearer token

  • User adds MCP URL + Authorization: Bearer <key> to Desktop config
  • Token is sent directly on each request
  • No OAuth redirect needed

MCP → WordPress

  • Server uses a single shared WP API token stored in .env
  • Token is scoped (read / read-write) and expiry-bound
  • Stored as SHA-256 hash in the WordPress DB
Design intelligence

How Claude knows the brand

A design-guide.md file lives in the active WordPress theme root. Every time Claude connects, it is instructed to read this file before building anything.

What the guide contains

  • Brand colours: Teal #2AD2C9 · Navy #002A3A
  • Horizontal rule above titles — the signature pattern
  • Text link style (border-bottom underline, no arrows)
  • Two-column label + content layout
  • Section types: hero, cards, stats, CTA banner, testimonials
  • What NOT to do: inline styles, colours outside palette

How it's delivered

  • Stored as design-guide.md in the theme — version-controlled
  • Retrieved on demand via get_design_guidelines tool
  • Updating the file takes effect immediately — no server rebuild
  • MCP server's startup instructions tell Claude to load it first
Security

Authentication layers

1
HTTPS everywhere All traffic encrypted via nginx + Let's Encrypt. WordPress plugin refuses requests without HTTPS.
2
OAuth 2.0 + PKCE (Claude.ai) S256 code challenge prevents authorisation code interception. No client secret stored on the user's machine.
3
Per-user MCP tokens Each user has their own label:secret in the server's API_TOKENS env var. Individual access can be revoked without rotating others.
4
WordPress plugin tokens Separate 64-char hex token, stored only as SHA-256 hash in the WordPress DB. Never exposed after creation.
5
Token scopes Read-only vs read-write scope enforced per token. Write permission also requires an explicit allow_writes toggle in WP settings.
6
Token expiry Each WP token has a set expiry (7 / 30 / 90 / 365 days). Expired tokens are rejected automatically.
Security

File system & access control

File system protections

  • Path traversal blocked — realpath() resolves symlinks; any path escaping the theme directory is rejected
  • Extension allowlist — only php css js json html svg md txt are readable or writable
  • Hard link guard — files with nlink > 1 are rejected to prevent hard-link aliasing
  • File size limit — reads capped at 1 MiB
  • Atomic creation — O_EXCL flag prevents create-overwrite race conditions
  • OPcache invalidation — PHP bytecode cache cleared after every write

Access control

  • IP allowlist — requests must originate from a configured IP or CIDR range (optional: skippable when behind a CDN)
  • Plugin on/off switch — entire API can be disabled without removing the plugin
  • Write switch — writes require both an enabled write policy AND a write-scoped token
  • CPT validation — custom post type access requires show_in_rest = true; private CPTs and attachments are blocked
  • WP user capability check — token owner must have edit_themes capability; token does not elevate WP session
Deployment

Infrastructure setup

MCP server stack

  • Hetzner VPS (116.203.115.78)
  • Docker container — Node.js 22
  • nginx reverse proxy at mcp.ai-circus.net
  • Let's Encrypt HTTPS via certbot
  • Path: mcp.ai-circus.net/wp-theme-editor/
  • Hub page lists all available MCPs
  • Each MCP has its own landing page with setup guide

Updating the server

  • Source: github.com/ai-circus/wp-theme-mcp
  • Update: git pull && docker compose up -d --build
  • WordPress plugin: upload zip via WP admin
  • Design guide: edit design-guide.md in theme — no rebuild needed
  • Secrets in .env — never committed to git

WordPress side: staging.contextflow.com sits behind AWS CloudFront. The plugin's "Skip IP check" toggle is enabled so CloudFront's rotating edge IPs don't block the MCP server's requests. Auth relies on the bearer token + HTTPS instead.

Security · Threat model

Threats & mitigations

!
Stolen MCP token Attacker can call MCP tools as that user. Mitigation: revoke token in API_TOKENS env + restart container. Tokens are never logged or stored in plaintext.
!
Stolen WordPress token Attacker can call WP REST API directly. Mitigation: revoke via WP Settings. Token only stored as SHA-256 hash — cannot be recovered from DB.
!
Path traversal attack Attempt to read ../../wp-config.php. Mitigation: realpath() resolves all symlinks; prefix check enforced; .. components blocked at input.
!
Prompt injection via WP content Malicious content in a page/post could instruct Claude to take unintended actions. Mitigation: user-in-loop for all destructive actions; Claude is instructed via project instructions.
!
Unauthorised writes Read-only token used to attempt writes. Mitigation: scope enforced at plugin level; write policy toggle is a second independent gate.
!
OAuth code interception Attacker intercepts authorisation code. Mitigation: PKCE S256 — without the verifier the code is useless. Codes expire after 5 minutes.
Summary

Key takeaways

For the team

  • Claude can build, edit, and publish directly on the WordPress site
  • Design guide ensures on-brand output without manual prompting
  • Works from Claude.ai web or Claude Desktop — no local setup

Security posture

  • Two independent auth layers (MCP + WP)
  • Writes require explicit per-token scope AND a settings toggle
  • File system access strictly sandboxed to active theme
  • Tokens expire and can be individually revoked
